# 客服微信登录接入要求（2026-11-08）

> 后续需求已调整并部署：用户选择“手工登记公司客服微信号 + 管理员一次性登记码”，数据长期归属于微信号，员工轮班不改变归属。填报入口的禁用微信登录选项已替换为登记表单，见 [CS_WECHAT_ACCOUNTS.md](CS_WECHAT_ACCOUNTS.md)。下文保留早期官方 OAuth 方案作为历史参考，并非当前登录流程；未来若启用官方登录，需要围绕业务微信身份重新设计绑定关系，不能照搬员工绑定方案。

## 用户确认

- 客服主要在手机微信里打开加粉和订单两个固定填报链接。
- 微信登录作为可选登录方式，账号密码登录保留。
- 公司暂时没有、或尚不确定是否有可用的微信公众号/微信登录资质。

## 当前交付与限制

客服两个入口的未登录页面新增「使用当前微信登录」选项，明确标注「待开通」并禁用。提示继续使用员工账号密码。没有模拟授权、识别微信身份、获取微信数据或自动开通员工账号。

真实微信登录尚未实现或启用；没有申请/登录公众号平台、没有配置微信 AppID/AppSecret，没有发送任何授权请求，也没有读取手机微信登录信息。

当前已部署系统仅监听 Windows 本机。外地手机微信暂时不能访问 127.0.0.1，须先完成国内云服务器、HTTPS 和正式域名部署。

## 开通前需要用户核实

1. 公司有无具备网页授权权限的已认证公众号；常见为已认证服务号，应以公众号后台实际接口权限为准。
2. 若无，使用公司主体申请合适账号并完成微信要求的认证。注册主体材料、认证与扫码操作由用户或公司账号管理员处理；本轮不代办或承诺审核结果、费用。
3. 在正式管理域名配置网页授权域名，并按平台要求部署校验文件。目标 cms.nanzhaoarts.com 仍未上线，不能填写 localhost 当作已完成授权域名。
4. AppSecret 只在服务器本地环境配置或密钥管理中使用，不放入前端、链接、日志、截图或聊天。

## 后续接入的身份及权限规则

这些是接入设计，不是已存在的功能：

- 客服首次以已有员工账号登录、完成强制改密，再授权绑定本人微信；不能仅靠昵称、头像或手填微信号匹配员工。
- 绑定后允许通过微信授权换取系统会话，仍沿用对应员工的角色、小组、审核和数据范围。
- 未绑定、停用的员工，或不属于允许填报角色的微信，不能直接获得填报权限；不自动开放注册。
- 不承诺获取用户可见的普通微信号。登录应使用微信官方返回的应用内身份标识（如 OpenID），不以浏览器 User-Agent 作为身份凭证。
- 只为身份认证申请必要权限；未确认需要头像和昵称，不额外索取手机号或通讯录。
- 一次性、带有效期并绑定当前会话的 state；服务端交换 code，不向前端暴露 AppSecret 或授权令牌；回跳路径只允许两个已知填报入口。
- 绑定/解绑应再次验证当前账号身份并留审计记录；绑定不能变成静默接管账号的通道。
- 回跳后保留原本打开的加粉/订单入口。
- 当前部署 COOKIE_SAMESITE=strict；接入外站 OAuth 回跳时需要评估并测试 Cookie 策略与 CSRF/state 保护。不能不经验证直接认定当前配置已支持回跳。

## 上线验收

取得有效公众号权限及正式域名后，再开发 OAuth 回调、身份绑定和撤销逻辑，追加迁移（已有 001/002/003 已执行，不修改历史迁移）。
隔离库测试必须包含 state 过期/重放、未绑定/停用拒绝、首次绑定校验、角色越权、账号密码回退和原入口恢复；之后才在真实手机微信中验证并启用按钮。

参考：[腾讯云 CloudBase 官方公众号接入要求](https://docs.cloudbase.net/integration/wechat-official-oauth)、[微信官方网页授权文档](https://developers.weixin.qq.com/doc/offiaccount/OA_Web_Apps/Wechat_webpage_authorization.html)。后者本轮网页工具无法直接访问，权限细节需以公司微信后台实际状态核实。
