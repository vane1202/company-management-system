# 后台管理员「模块管理」改版（2026-11-18）

## 开关一览

| 开关 | 停用后被拒绝的写入 | 受影响角色 |
| --- | --- | --- |
| 客服加粉（fans） | 加粉日报、线索明细 | 客服（客服主管只读，不受影响） |
| 运营投放（ops） | 推广日报、广告账户 | 运营、财务 |
| 拍剪日报（editor） | 拍剪日报 | 拍剪 |
| 订单（orders） | 订单、订单明细、跑单与取消登记 | 客服 |
| **库房结账（warehouse，新增）** | 库房提交、重新提交对外结账单（`/api/warehouse`） | 库房 |

停用只拒绝写入，读取照常，历史数据保留；人员、权限、工资、财务收付款和本页始终可用。每项的说明文字来自后端 `MODULE_DETAILS`，改守卫时请同步修改，并保持与 `app.ts`、`access.ts` 一致。

## 本次变化

- **库房不再绑在「订单」开关上。** 之前 `/api/warehouse` 与 `/api/finance/warehouse` 都用 orders 开关，关闭订单会让库房无法提交，且财务也无法审核、付款。现在库房提交端使用独立的 warehouse 开关；**财务端 `/api/finance/warehouse` 不受任何模块开关限制**，已提交的账单始终可以审核、付款、结清，避免欠供应商的款项付不出去。
- **兼容旧配置。** 数据库里已保存的配置没有 warehouse 键时，按“启用”处理，不需要迁移；其他键缺失或类型错误仍然拒绝启用（失败即关闭）。
- **接口**：`GET/PUT /api/modules` 新增 `details`（每项说明与影响角色）和 `lastChange`（最近一次修改的时间与人，仅管理员可见，来自审计日志；查询失败时为 null，不影响主流程）。
- **页面**：开关样式；每项显示影响范围；改动后标“未保存”并提示数量，没有改动时保存按钮不可用；可放弃修改；停用前二次确认，重新启用不确认；提交时只发送被改动的项；显示上次修改人和时间；库房人员在开关关闭时看到“库房结账已停用”的说明，而不是填完才报错。
- 演示站的模块接口同步（标签统一为「拍剪日报」）。演示站会统一禁用所有表单的提交按钮，所以保存流程只能在正式构建中验证。
