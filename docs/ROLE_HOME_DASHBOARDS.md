# 管理员与客服主管首页（2026-11-09）

用户要求继续完善原先只有按钮入口的两类管理首页。本次只更新前端，沿用现有 API 和服务端权限，不修改数据库、账号或分组。

## 后台管理员

- 首屏展示员工账号、已建小组、已登记微信、启用模块。员工账号数排除 `cs_wechat` 公司微信身份；停用账号、停用微信单独提示。
- 下方提供账号与小组、客服微信、模块与系统设置的管理入口，以及未分组启用主管、未归组启用微信、模块启停状态。
- 只读取 `/api/admin/users`、`/api/admin/teams`、`/api/cs-accounts`、`/api/modules`。不请求加粉、订单、经营估算、工资等业务接口。

## 客服主管

- 首屏展示已授权小组的今日加粉总数、今日有效、取得沟通（正常回复）、无效客源（无效粉）。
- 今日订单展示 API 返回的金额字符串、有效订单数及退款金额。金额包含退款源订单，退款单列；有效单数排除退款订单，不自行用浮点数累加金额。
- 今日填报进度按微信与原员工账号计数，多主页不重复计数，填报 0 仍属于已报。下方分小组显示应报、已报、未报及未填报账号。
- 微信概况展示本组已登记及启停数量，可进入登记维护页。
- 仅读取现有 `/api/fan-reports/summary?date=...`、`/api/orders?from=...&to=...`、`/api/cs-accounts?date=...`。日期来自会话返回的东八区业务日。小组范围由服务端决定，首页不请求全局经营接口。
- 尚未分配负责小组时显示说明，不显示伪造的业务零值。各数据源独立加载；接口失败显示“—”及重试提示，保留其他成功数据。
- 首页固定看今日；“全部消费”进入全部可见订单，历史日期及微信筛选继续在各明细页使用。

## 布局与操作

沿用白底和现有色彩，不引入依赖。手机端三个管理角色统一采用紧凑品牌栏、可展开的全部菜单、底部导航；隐藏重复的顶部横向导航和面包屑，菜单中保留退出登录。桌面保留侧栏。底部客服微信入口使用短标签，避免窄屏换行。

两端的四项指标均在 320×568、360×640 的首屏内，页面无横向溢出。线上 360×640 中管理员指标底边约427px、主管约389px；主管订单概况底边约575px，底栏顶边579px。
