# 岗位工作台优化 · 第一阶段

日期：2026-11-13。目标为独立演示站；本次未部署、未推送 GitHub、未更新正在运行的本地后台，也未执行数据库迁移。

## 目标与范围

每个岗位首页回答“今天先处理什么”，将常用操作和可从现有数据判断的待办放在前面。沿用现有模块权限、业务汇总和明细接口。

- 客服：新增工作台首页，顺序为每日加粉、开单记录、售后费用、入场登记。子页提供返回工作台与四项切换；切换页保留试填草稿，确认换号后清空所有页草稿。
- 入场登记：入口放在客服端，填写日期、主播/直播间、当前账号持有人、实际入场客户人数、核对来源与备注。人数为非负整数，允许0，拒绝未来日期；未设置持有人不能检查。此阶段仅试填，不保存、不接入考核汇总。
- 客服主管：首页优先展示报粉进度、未报账号、今日开单营业额、在用账号；将缺报跟进、开单与尾款核对、补持有人及本组管理集中展示。入场登记不放在主管工作台。
- 财务：按收款与结算、付款与工资分组展示六个常用任务。收款卡片为已登记且未作废的流水笔数；第三方待结算按余额大于0计数，余额缺失显示待核对。其他工具折叠。保留既有收款、结算、供货款、公司支出与工资工作区。
- 管理员：只读取账号、小组、接待账号和模块配置，展示未分配主管范围、账号未分组、缺持有人等配置事项，不读取业务数据。
- 修复财务及拍剪演示的“检查试填内容”按钮被通用只读保护误禁用的问题。仅本地校验，不开放任何业务写接口。

## 口径与后续阶段

实际入场人数来自私域直播间后台，同一客户同日同直播间只计1人，跨接待账号重复需要人工核对。入口位置已确认在客服端，当前提供数量试填，尚无客户级去重与持久化。

新考核的开口转化率、开单客户比例、无效粉运营反馈，以及稳定员工ID、账号任期、人员交接封存和历史归属不在本阶段实现范围。当前持有人显示不代表人员历史归属已经完成。旧有数据页仍沿用原有口径。
