# Windows 局域网访问（2026-11-08）

用户反馈同一局域网手机无法访问。原因：原应用只绑定 127.0.0.1，允许来源也仅有本机地址。

现已部署：

- 本机继续使用 `http://127.0.0.1:13080`。
- 同一局域网使用 `http://192.168.1.58:13080`。
- 保持原本机监听，额外仅绑定以太网地址 192.168.1.58，不绑定 0.0.0.0、VPN 的 198.18.0.1 或 IPv6。
- 新增 LAN_ALLOWED_CIDR=192.168.1.0/24，应用直接按 socket 源地址限制额外入口；X-Forwarded-For 不能改变判断。
- APP_ORIGIN 显式增加局域网来源，保留原来源和 CSRF/同源校验；账号及角色权限不变。
- PostgreSQL 16543 保持 127.0.0.1，没有开放给手机。

查看到 Windows Private/Public 防火墙配置原本已关闭，本轮没有修改其启停。额外添加 `Cuiguanjia-LAN-13080` 入站允许规则，为未来启用防火墙保留访问：仅 Private 配置、以太网、192.168.1.58:13080、专用 Node 路径、来源 192.168.1.0/24；不允许边缘遍历。当前网段限制仍由应用执行，不依赖已关闭的防火墙配置。

## 验证

本轮无数据库回归 45 项（含新增局域网 4 项）和独立权限集成 14 项通过，后端构建、局域网测试 TypeScript 检查通过。验证明确私有网段配置、同网段访问、不同子网/VPN 拒绝、转发头不可冒用、LAN 来源显式列入、CSRF 不可缺失；没有测试手机实机。

安装前保留原后端和受保护环境配置。修改后的后端文件逐一比对 SHA-256；原计划任务恢复后，本机和 LAN 健康检查均 ok。实测匿名会话通过 LAN 获取 CSRF 并退出成功，未列入的 VPN Origin 返回 403；没有登录真实账号或写业务数据。

配置及备份路径清单：安装目录 `backups/lan-access-configuration.json`。包含配置备份路径的文件也在受保护安装目录；不应对外分享环境配置。

## 手机连接

连接与电脑相通的同一局域网 Wi-Fi，在浏览器直接打开以上 LAN 地址。手机上的 localhost/127.0.0.1 指向手机自己，不是这台电脑。访客 Wi-Fi、AP 客户端隔离、手机 VPN 路由或不同子网可能阻止访问，需要进一步根据手机实际网络排查。

电脑须开机运行后台。如果以太网 IP 更换，应更新 LAN_HOST、LAN_ALLOWED_CIDR（网段变化时）、APP_ORIGIN 与对应防火墙规则，不能继续假定旧地址有效。本轮未改路由器、DHCP 或公网端口映射。

域名演示为另一个独立任务，不会因此把正式本地后台接到公网。
