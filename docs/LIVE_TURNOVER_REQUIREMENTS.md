# 直播间营业额口径 · 待完成细节确认

来源：用户在直播间经营分层导航完成后的业务说明。本文件区分已确认事实与待确认规则，不代表统计代码已完成调整。

## 已确认

- BOSS关注的首项指标为“当日营业额”，应依据直播间开单卡记录，不以客户当日付款或公司当日到账为计入条件。
- 客户预定料子后，主播填写开单卡，记录客户ID、开单金额和代购费用；客服据此联系客户沟通付款。
- 客户在次日或约定日期付款，仍计入原开单日营业额。后续收款应登记为收款流水，不再次增加开单营业额。
- 业务日期应对应开单卡日期；填报日期、客户付款日期及第三方结算日期分别保留。
- 后续发生爽约跑单，需要关联原订单记录冲抵，保留原始开单及变更轨迹。

## 待确认

1. 跨日跑单：在确认跑单日记录冲抵，或回冲原开单日。尚未选择，不能将建议当作已确认规则。
2. 首项营业额是否仅含开单卡料价及代购费；设计雕刻等后续追加收费是另列还是一并计入。

## 现有实现与差距

- 当前直播间经营接口按订单business_date生成成交事件，不要求已收款，已支持开单日与付款日分离。
- 当前业绩合计为新增成交加追加收费，尚不能视为用户已确认的新营业额范围。
- 当前按订单最新refunded状态排除源单，缺少独立的跑单冲抵日期与事件；该方式会改变历史汇总，不能直接充当新规则的冲抵实现。
- 未付款跑单与实际收款后的退款需要分别记录，不能为了冲抵营业额而生成不存在的退款资金流水。

待上述规则确认后，再调整统计、订单操作、首页及收入明细，并验证跨日收款不重复计入、冲抵可追溯且不误改资金流水。
