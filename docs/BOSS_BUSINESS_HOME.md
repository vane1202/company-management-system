## 用户确认的展示顺序

1. 直播间当日业绩：当期新增成交＋当期追加收费。
2. 直播间当日费用：按业务费用各自的发生日期。
3. 运营成本：本轮仅显示全公司广告消耗 USD，不包含工资或充值实付。
4. 直播间经营明细：直播间、主播、人设、业绩、费用、新增订单。
5. 全公司加粉数据、视频拍剪数据。
6. 今日填报进度。

手机前三项纵向排列，电脑三栏并排。日期支持今日、本周、本月、自定义范围；快捷周期会同步日期输入，避免输入日期与实际统计范围不一致。

## 发生日期与金额

新增只读接口：`GET /api/dashboard/live-business`，仅 BOSS 可访问。读取使用一致的只读数据库快照。

| 指标 | 来源及日期 | 说明 |
| --- | --- | --- |
| 新增成交 | 原订单 `business_date`，商品料价＋对应代购费 | 已有明细的订单只取原始商品报价，不把后续追加收费再算入原成交日 |
| 追加收费 | 有效 `order_charges.business_date` | 旧订单今天追加收费，会进入今天的业绩 |
| 业务费用 | 有效 `order_expenses.business_date` | 供货、加工、配货、证书、配件、包装、运费各自计入发生日 |
| 客户实际付款 | 有效 `customer_payments.payment_date` | CNY、TWD、USD分别展示，不自行换汇 |
| 公司人民币净到账 | 直接人民币收款日＋第三方结算到账日 | 结算只取该笔订单的净到账分配，不重复扣费 |
| 公司实际付款 | 有效 `supplier_payments.paid_on` | 与业务费用分别显示，不用实际付款代替费用发生额 |
| 运营成本 | `ops_reports.business_date` 对应的已登记美元消耗 | 不包含广告充值或任何工资 |

当前标记为退款的订单不计入有效业绩，源单金额单列“已标退款源单”。现有结构没有独立退款日期/部分退款流水，所以这里不称为“今日实际退款”。历史缺少费用发生日的旧成本显示待核对，不推测为当期费用。

消费汇总的整单档案、原经营估算仍沿用原来的订单日期口径；本次首页使用发生日期口径。旧订单全额报价与今天追加收费可能不同，首页明细可以直接打开原订单核对。

## 筛选与下钻

- 直播间、主播、人设ID、对接客服筛选影响业绩、费用及相关资金流水；未归属直播间保留在总数和明细中。

- 支持按业绩或费用排序。点击直播间行展开收支，点击三项核心卡片展开对应明细。
- 明细中的“查看订单档案”进入原订单，沿用既有列表/首页返回链路，保留首页筛选。
- 页内明细提供固定返回栏；返回列表后恢复展开前的位置。
- 数据读取失败显示错误和重试，空范围显示明确空状态；不会把读取失败伪装成0。
