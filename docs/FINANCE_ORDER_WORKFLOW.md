## 账号和权限

管理员登录本地后台，在「账号与小组」新增员工时选择「财务」，设置登录名、姓名和初始密码。首次登录需自行改密。此次新增角色及开通入口，没有擅自创建实际财务人员或重置原有账号。

| 角色 | 业务范围 |
| --- | --- |
| 财务 | 查看客户收款和第三方待结算，登记扣点、实际扣费、结汇及人民币净到账，匹配多笔付款/部分结算，附原因作废错误结算。不能管理账号、小组和模块，也不能看工资、推广、拍剪、订单成本和原图。 |
| BOSS | 原有汇总和明细只读；新增「收款与结算」入口，查看实际人民币累计流入及分币种待结算。禁止写入。 |
| 后台管理员 | 只管理账号、小组、微信登记、模块和设置。禁止读取或修改收款、结算、订单明细、成本和附件。 |
| 客服主管 | 读取订单业务日归属本组的订单档案及附件，管理本组客服微信。不拥有填报或财务写权限。未分组仍为空范围。 |
| 客服微信 / 原客服账号 | 只录入和查看本主体的订单、逐笔付款、发货费用、发货日期和原图。经办客服姓名作为快照记录，不改变数据归属。 |

权限由后端认证后的角色边界和订单范围检查共同执行，隐藏入口不代替授权。原 `/api/orders` 修改接口不能覆盖新明细订单的金额。

## 客服操作

1. 从固定 `/fill/orders` 入口登记公司微信或使用原账号登录。点击「登记一笔成交」。
2. 填成交日期、订单编号、人设/主页、经办客服、客户称呼或内部编号、来源/直播间和备注。
3. 逐件填商品类别、名称/料号与人民币谈成价。原石代购费逐块按10%计算，采用四舍五入到分；成品不自动加费。此为本次计算实现方式，未改变旧订单金额。
4. 选择客户约定付款币种。人民币应收自动等于料价加代购费；台币/美元须明确录入双方约定总应收，不倒推或调用实时汇率。
5. 在订单档案继续记定金、尾款或全款。每笔保留付款日期、原币金额、账户/第三方、流水号和备注。与应收币种不同时，明确录入双方认可的抵扣应收额。
6. 售后补记商品/料子成本、工费、证书、包装盒、运费或其他人民币费用，登记发货日期。费用合计与成交、付款独立。
7. 上传成交/成本留底原图，可关联整单或具体商品。照片中的手写价需人工核对，系统不自动识别定价。

没有有效收款、尚未发货或标记退款的订单可「更正成交」，填写原因并校验版本，保留前后快照。更正明细时原照片保留在整单，原商品关联在修改轨迹中留存。有有效收款的订单先核对并纠正错误关联记录，不能直接改成交。

错误付款、费用和结算支持附原因作废，原记录保留；重复提交同一作废不会重复影响成本或余额，也不覆盖原原因。已关联有效结算的付款不能由客服直接作废，须财务先纠正结算。作废用于登记纠错，不代表资金退款。

## 财务操作与金额口径

- 首页先看实际人民币累计流入、人民币直接收款、第三方净到账，及 CNY/TWD/USD 各自待第三方结算。原币金额不相加为单一金额。
- 「登记第三方结算与到账」选择同一账户及币种，填写到账日期、唯一结算流水号、扣点百分比（可选）、实际扣费及币种、已知实际汇率（可选）、实际人民币净到账和备注。
- 勾选相关客户付款，逐笔填本次结算的原币与分配的人民币净到账。支持多单、部分结算；人民币分配合计必须等于本次实际净到账，不自动平均分摊。
- 第三方原币待结算 = 有效代收原币 − 有效结算分配原币。已作废的付款和结算不参与有效合计。并发结算锁定相关收款，防止超额分配。
- 客户尾款 = 客户约定应收 − 有效付款认可抵扣额。客户向第三方付清后即已结清，公司承担扣点与汇差；后续结汇不更改客户尾款。
- 公司人民币累计流入 = 有效人民币直接收款 + 有效第三方人民币净到账。净到账已体现扣费，不能再扣一次手续费。
- 收款可按付款日期、币种、账户、订单/客户/微信/流水号筛选，并可仅看待结算。结算记录按公司到账日期排列，展开可追溯分配明细。订单列表沿用成交日期、微信和订单状态筛选，并可查客户/编号。

## 存储和兼容

- 追加迁移 `005_finance_role.sql`、`006_order_workflow.sql`。新成交只在原 orders 表记一笔成交总额，料价及代购费明细单独保存。
- 费用同步兼容字段：商品/证书/包装/其他合计进入 `custom_product_cost`，工费进入 `labor_cost`，运费进入 `shipping_cost`。原统计从兼容字段读取，不能再叠加费用明细重复扣除。
- 付款、结算和费用有提交标识及内容摘要，网络重试不重复入账；改动同键内容返回409。收款总抵扣不得超过约定应收，同一账户/币种有效流水号去重。
- 原图保存于 PostgreSQL 受保护 BYTEA，随完整数据库备份；每张≤8MiB、每单≤12张，支持 JPEG/PNG/WebP，检查大小、类型及签名，不接受 SVG。按订单权限读取，响应为私有不缓存，不进入公开静态目录。暂未建设云端对象存储。
- 旧简版订单保留原始金额及成本，标记“收款状态未知”，不补造币种、逐笔付款或已结清状态，不直接向旧单新增新收款/费用。
- 经营估算仍以成交报价及已有成本计算，不是实际到账净利润。财务首页是流入流水，不含实际退款流出；部分退款、退款日期、退款费用冲回仍需后续独立设计。工资写入岗位仍未开放给财务。
