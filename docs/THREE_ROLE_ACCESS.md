## 授权实现

`backend/src/lib/access.ts` 在认证/首次改密保护之后、业务路由之前统一拦截角色边界。认证、退出和本人改密走原认证路由，仍可正常使用。权限由服务端实施，不依赖隐藏导航。

主管消费列表、导出及消费合计均按订单业务日的成员归属与授权小组求交集。查询其他微信 ID 也不能越过小组范围；使用 EXISTS 避免多份归属使订单重复。未来调组不把较早订单提前暴露给新组。新筛选支持开始/结束日、订单状态、审核状态、客服微信。消费与退款合计由服务端按分精确相加，退款源订单仍包含在消费合计中，界面有明确说明。

微信管理接口每次检查目标微信当前小组。主管可以发本组登记码及重登记码、更新同一业务微信的号码/设备备注、启停。更正微信号会保留原业务 ID 和历史数据，但撤销旧会话及未用重登记码，需要重新发码。若实际上换成另一个微信，应新登记，避免混合数据。

后台管理员可通过新增界面设置主管的多个负责小组；更新范围有事务与审计。员工角色/启停调整序列化，并禁止停用或降权最后一个启用的管理员。

原运营、拍剪、助理、客服填报角色继续保留。三类管理账号都未获得工资写入权限，BOSS 只查看已有工资及分摊结果；如果以后需要维护工资，应单独确定具备该业务权限的岗位。
