# BOSS 收款与到账看板

2026-11-11，用户确认优化「收款与结算」的 BOSS 展示，继续仅更新独立演示站；Windows 本地安装后台暂不更新。

## 展示顺序

1. 公司已到账：所选期间的人民币直接收款＋第三方实际人民币净到账，直接和代收转回作为小项。
2. 代收未转回：截至所选结束日的已登记原币余额，包含历史付款，台币、美元分别列示。
3. 客户已付款：按付款日统计期间有效付款，原币分别列示。
4. 代收跟进：按账户与币种分组，列出待转回金额、涉及笔数、最早付款日、已代收天数和最近转回日期；可筛选、展开查看相关客户和订单。
5. 本期公司到账：按到账日期列出直接付款、代收转回和关联订单。
6. 财务明细默认收起，完整结算、手续费、汇率、公司付款、核定业绩和广告台账仍可查询。

导航与页面标题在 demo BOSS 模式下改为「收款与到账」。真实财务填报表单及权限没有调整，正式构建仍使用原工作台。

## 金额与日期口径

- 日期提供今日、本周、本月、自定义区间。期间流入和期末存量分别标注，不直接相减。
- 公司已到账按直接收款付款日、代收公司到账日统计，净到账已反映扣费，不再重复减手续费。该指标为已登记人民币流入，不代表银行账户余额、不含退款流出，也不是利润。
- 代收余额由截止日前的有效客户付款减去截止日前有效结算分配原币重算，不沿用当前 `pendingAmount` 或 `settled_amount` 快照。截止日之后的付款和结算不提前计入，开始日之前的未转回款仍保留。
- 各币种不相加，不用参考汇率推算人民币实际到账。缺失或错配分配、超额结算等金额显示待核对，不显示负余额或伪造零余额。
- 客户付款与代收转回分开。代收未转回不等于客户欠款；客户未付款仍在直播间经营的订单跟进中查看。
- 天数从最早未转回付款日算至结束日；没有约定转款期限，不判定逾期。只根据当前有效记录重算，不宣称提供完整历史版本快照。
- 点击客户付款卡，展开财务明细并按选定付款日期筛选全部有效付款；点击具体代收流水，按流水／订单号筛选，包含已直接到账或已结清收款。完整财务累计汇总与各子台账保留原口径，页面有明确说明。

## 发布前完整性复查

用户追加要求检查最近改动完整性。复查发现并修复：

1. 历史日期没有待转回记录时，账户选择列表会丢失已选项。现从完整已登记代收账户生成选项，保留当前选择；历史空状态下仍能看清筛选条件。
2. 汇总复用了单笔输入的 12 位整数限制，金额超过该限制时可能被误标为缺失。现汇总用不限单笔位数的整数分值计算，显示也不经过浮点数，分位保持精确。
3. 日期或币种无法归类的异常记录会被略过，可能将未知余额显示为已确认的 0。现相关汇总和账户余额显示待核对，空状态不再宣称余额为零。

复查结果：前端 82 项＋只读演示与经营指标 48 项，共 130 项测试通过。实际演示 API 的公司到账、原币未转回余额与新看板一致，契约测试确认无正式后台网络请求。BOSS 写入被拒绝，财务端保留原工作台和登记入口，BOSS 完整明细未出现写入操作。

静态包 17 个文件、19 处资源引用检查通过，各文件字节数与 SHA256 均与清单一致；标准 production 产物没有包含新资金看板。未连接真实业务数据库、未运行迁移、未更新 Windows 安装副本。本次验证的是独立演示的完整性，不替代真实财务格式与实际数据验收。
